Two-Child Deletion Strategy (BST)

For deleting a node with two children, I used the in-order successor method we talked about in class. I  first located the successor by finding the minimum node in the right subtree, remove it using detachMin(), and replace the deleted node with that successor. Then I reattach its children appropriately. This preserves BST ordering and keeps the structure valid.

Guardrail / Design Choice

I enforced a strict duplicate policy as follows: duplicates are defined as having the same (name, category) pair. The BST ignores duplicate inserts, and Engine::add returns false when a duplicate is detected. The hash table is keyed by name, so the Engine checks both structures before inserting to keep them consistent. This guardrail prevents mismatched states between the hash table and BST and ensures the collection always maintains unique items.
